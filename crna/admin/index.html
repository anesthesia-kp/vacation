FTE Availability
Set how much FTE is available each week. Every week shows its current value — change a number and save. These values are used everywhere: user bidding boards, the dashboard, draws & reviews, and outcome calculations.
🔐 Smart Lock Control — what it does
Smart Lock Control is the minimum remaining FTE a week needs to stay open. When Smart Lock runs (between phases, or from the dashboard), each week is compared to its own control value: remaining FTE below the control → the week locks (or stays locked); remaining FTE at or above the control → it unlocks (or stays unlocked). Range −1.0 to +1.0 in 0.1 steps; every week starts at 0.4.
Examples: control 0.4, week has 0.3 remaining → locks. Control 0.4, week has 0.4 remaining → stays open. Control −0.2, week has −0.1 remaining → stays open (−0.1 is above −0.2).
How to use it: leave everything at 0.4 and Smart Lock handles the whole year automatically between phases. Lower a week's control (even negative) to keep that week biddable deeper into overage; raise it to close a week off earlier.

⏱ Timer Rules ▸ Show
The bidding countdown resets every time someone bids. It starts long and gets shorter as the round goes on. When the reset gets short, bidding won't close overnight. Adjust the days, the reset lengths, and the overnight window below — edits stage here and nothing reaches the database until you press Save (one confirm covers the whole batch).
⏱ Timer Reset Mode
Which bid activity restarts the countdown. The classic rule stays in force until you deliberately pick another mode — a change asks you to confirm, is recorded in the Change Log, and the staff page's Timer Rules text updates to match, so bidders always see the rule in force. Stage lengths, the opening window, and the expired-timer guard apply in every mode; simulator runs keep their single batch reset.

📧 E-mail Sending Controls
Outbid alert e-mails
When ON, users get an e-mail whenever their projected outcome for a week changes (from a real user's bid, an admin bid change, or the simulator). When OFF, no outbid alerts are sent from anywhere. Turn OFF during testing to avoid barraging users and burning EmailJS quota.
Welcome e-mails
When ON, each user gets a one-time welcome/rules e-mail at their first login (and when a KP e-mail is added for an already-logged-in user). When OFF, no welcome e-mails are sent. Turn OFF during testing. Addresses are still tracked, so turning it back on won't re-send to anyone already welcomed this cycle.
KP E-mail Prompt on Login
Ask users for their KP e-mail at login
When ON, a user who hasn't yet saved a Kaiser (KP) e-mail is prompted for it right after signing in with Google. On that prompt they can save it, pick "Remind me later" (asked again next login), or "No thanks — don't ask again" (never asked again). If they decline, you can still add a KP e-mail for them on the Users tab — that address gets one welcome e-mail when you save it. Once set, the KP e-mail receives every alert the Google login e-mail receives, and it appears on both admin sites.

🎚 Bid Floors by Week Category
The minimum bid strength allowed per week category — a bid may be placed only if it is at least as strong as the week's floor (strength order: 1/2/3 › 1/2 › 1 › 2 › … › 10 › NP). NP is the weakest bid, so any numeric floor blocks NP on those weeks; where "No floor" is set, NP still follows the per-phase toggles above. Enforced in the bid picker AND the decision engine on both sites. Changing a floor affects NEW bids only — existing bids stay as placed. Cumulative Bid Caps (max weeks per user)
Maximum weeks a user may WIN, cumulatively, through each phase
Each cap is a running total through that phase (current phase + all prior phases). Only weeks a user wins count against it — denied/lost bids never count. In the current phase it counts the user's prior-phase wins + their live bids this phase. Check No limit for a phase with no cap. A phase that has a number can only be the same or higher than an earlier numbered phase — later values fill in automatically and can only be raised. Changing a value asks you to confirm before it saves.
FTE Overage Amount
Maximum FTE Overage
Shapes PROJECTIONS during bidding: how far over capacity a bid can be and still become a DRAW (each tied user must fit within this amount) or UNDER REVIEW (single user over cap by this amount) instead of an automatic loss. Range 0.0–2.0, step 0.1. Default 0.5.
You can adjust this setting between phases. It locks while the current phase has bids; once a phase completes (and before the next phase takes bids) you can change it. Past phases are unaffected — their results are frozen at completion — so a change only applies to the current and later phases.
